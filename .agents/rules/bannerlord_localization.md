# Bannerlord Localization Architecture & Constraints

When implementing text localization, adding new UI strings, or updating dialogues in Mount & Blade II: Bannerlord, you MUST follow the engine's localization architecture and encoding constraints.

---

## 1. Directory Layout & Manifest

Localization files must reside in language-specific subdirectories under `ModuleData/Languages/`:

```
Modules/<YourModId>/
└── ModuleData/
    └── Languages/
        ├── language_data.xml         ← Language manifest registering supported languages
        ├── EN/
            ├── strings.xml           ← English base translation
            └── language_data.xml     ← Optional language definition
        ├── ES/
            └── strings.xml           ← Spanish translation
        └── ...
```

### Manifest Registration (`SubModule.xml`):
Declare the language XML category in `SubModule.xml`:
```xml
<Xmls>
  <XmlNode>
    <XmlName id="LanguageData" path="Languages/language_data" />
  </XmlNode>
</Xmls>
```

---

## 2. Localization XML Schema (`strings.xml`)

Every translated string is defined inside `<strings><string id="..." text="..." />`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<base xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xmlns:xsd="http://www.w3.org/2001/XMLSchema" type="string">
  <tags>
    <tag language="English" />
  </tags>
  <strings>
    <string id="forge_welcome_msg" text="Welcome to the Calradia Forge Command Deck." />
    <string id="forge_caravan_escort_t" text="Caravan Escort to {TARGET_CITY}" />
    <string id="forge_multiline_dialogue" text="First paragraph of instruction.&#10;&#10;Second paragraph after line breaks." />
  </strings>
</base>
```

---

## 3. Critical Engine Constraints & Crash Guards

### A. Encoding: UTF-8 with BOM (`utf-8-sig`)
- Bannerlord's native XML parser will fail to read non-ASCII characters (e.g. accented letters `á`, `é`, `í`, `ó`, `ú`, `ñ`, umlauts `ä`, `ö`, `ü`, and Cyrillic/Asian characters) unless the file is saved as **UTF-8 with BOM**.
- Saving files as plain UTF-8 without BOM results in garbled text or parsing crashes.

### B. Newlines Must Be Encoded as `&#10;`
- The XML streaming parser strips raw LF (`\n`) and CRLF (`\r\n`) within attribute values (`text="..."`).
- **MANDATORY:** Always replace newlines in text attributes with `&#10;`. For multiple paragraph breaks, use `&#10;&#10;`.

### C. XML Special Characters Escaping
Never include raw characters in `text="..."`:
- `&` must be written as `&amp;`
- `<` must be written as `&lt;`
- `>` must be written as `&gt;`
- `"` must be written as `&quot;`

### D. No Dynamic String Concatenation Inside Localization Tokens
- **PROHIBITED:** Never concatenate dynamic values inside localization keys:
  ```csharp
  // WRONG - Breaks hash lookup and generates unindexed keys:
  new TextObject("{=text}Hello " + hero.Name);
  ```
- **MANDATORY:** Always use `TextObject.SetTextVariable` or string formatting after resolution:
  ```csharp
  // CORRECT:
  new TextObject("{=forge_escort_t}Escort to {DESTINATION}")
      .SetTextVariable("DESTINATION", destinationSettlement.Name);
  ```

---

## 4. Hash-Based vs Explicit String ID Lookup

1. **Explicit String IDs (Recommended for UI & Quests):**
   - Format: `{=unique_id}Default English Text`
   - Example: `new TextObject("{=forge_menu_trade}Open Black Market")`
   - When the localized key is found in the current game language's XML, the engine substitutes the localized text. If not found, it gracefully falls back to `"Open Black Market"`.
2. **SHA-256 Hashed Strings (`GameLocalization.cs`):**
   - Used for automatic localization pipelines where string IDs are generated by hashing the English string.
   - Run the synchronization script to propagate new English keys to all supported languages:
     ```bash
     python .agents/skills/bannerlord-localization/scripts/sync_langs.py
     ```
