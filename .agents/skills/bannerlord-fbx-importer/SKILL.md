# Bannerlord FBX Importer

This skill applies only to **BannerlordFbxImporter/**, a standalone .NET 8 Windows experiment. It is separate from the game module and release ZIPs. Read its English or Spanish README and current source before changing behavior; the README is the detailed, versioned evidence record.

## Safe local planning and tests

- Choose an explicit profile: **static-mesh**, **rigged-mesh**, **texture-only**, or **texture-assign**. Mesh profiles scan FBX; texture extensions are configuration derived from observed picker filters, not a TaleWorlds compatibility guarantee. **texture-assign** requires a complete explicit file-to-texture/material/slot map and does not itself perform assignments.
- Preserve scanner bounds: at most 100 files, depth 32, 10,000 directories, 100,000 entries, 256 MiB per file, and 2 GiB per batch. Repeated case-insensitive base names are rejected. A source root that is itself a reparse point is rejected; reparse points encountered below the root are skipped.
- Treat FBX material text parsing and the optional material manifest as advisory preflight only. Binary, malformed, or oversized FBX and unavailable/invalid manifest data require manual review; they do not prove import success. The helper cannot validate Blender export settings, leaf bones, rig weights, or Editor material registration.
- **--dry-run** is filesystem-only and must not connect to UI Automation or write to the module. **--inspect** is read-only. Run the fixture suite with **Test-BannerlordFbxImporter.bat**; do not start a compiled test executable directly, and do not use fixture results as proof of live Editor behavior.

## UI Automation and state claims

- Inspection must target the configured Editor process and exact visible **Resource Browser** top-level window. Do not confuse it with **Edit Mode**, even if both windows share a process. Reject zero or multiple matches.
- **--inspect** sends no clicks, selections, keystrokes, or dialog commands. The separate **--open-import-picker** mode may invoke only one exact, visible, enabled **Import New Assets** menu item under the configured Resource Browser when that menu is already open and UIA exposes `InvokePattern`; it does not select a file or import it. The helper's past invocation timed out, so do not claim this mode opened the picker without observing it.
- If UIA blocks or times out, the hierarchy is unavailable, a dialog is unexpected, or the state is otherwise uncertain, record **UNKNOWN** and stop. Never retry, dismiss dialogs, guess coordinates, or continue the batch from an uncertain state.
- When maintaining UIA discovery code, scope queries to the already resolved Resource Browser window rather than walking the desktop root. Microsoft documents that the UIA tree is dynamic, can be large, and cross-process tree walking can be costly; prefer a bounded search from the known window and require a single matching element. If a stored `AutomationElement` becomes unavailable, Microsoft defines `ElementNotAvailableException` for UI that no longer exists: treat it as **UNKNOWN**, leave the Editor unchanged, and do not reuse the stale element or retry globally. See Microsoft's [UI Automation tree overview](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-treeoverview), [TreeWalker API](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.treewalker?view=windowsdesktop-10.0), and [`ElementNotAvailableException`](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.elementnotavailableexception?view=windowsdesktop-10.0).
- Retrieve the required control pattern and fail closed if it is unavailable. Microsoft notes that attempting to retrieve the pattern and checking for `null` can avoid an extra cross-process query compared with separately checking pattern availability; see [UI Automation control patterns for clients](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-control-patterns-for-clients).
- The current code intentionally keeps **--submit** locked before UI interaction. Do not bypass it with appsettings flags or hand-written calibration records. No successful PNG/FBX import, TPAC generation, automatic replacement, or Model Viewer review is established by the current evidence.
- Use the state names precisely: **PLANNED**, **TARGET_READY**, **SETTINGS_READY**, **SUBMITTED**, **IMPORTING**, **OUTPUT_OBSERVED**, **VERIFIED**, **STOPPED**, and **UNKNOWN**. **SUBMITTED** means only a confirmed final Import-button action; **VERIFIED** requires observing the expected resource name and type in Resource Browser. Record visual Model Viewer review separately.
- Backup and replacement helpers are safety primitives only; they are not connected to the import flow. Never replace a resource unless the exact affected resource and its backup file set and SHA-256 have been verified and the replacement UI has been calibrated.

## Current evidence boundary

A user-confirmed project interaction on 2026-09-26 identifies the generic Resource Browser entry point: right-click blank space in the central **Assets** pane (not the left module/folder tree) and choose **Import New Assets** to open the separate Windows file picker. This establishes only the menu and picker entry point, not file acceptance or successful import. The local README's 2026-09-23 observation of the picker recorded a combined filter for **.tif, .psd, .dds, .bmp, .tga, .png, .hdr, .exr, .trf, .fbx, and .stsdk**; the eight observed raster filters are recorded in the `texture-only` and `texture-assign` profiles in `appsettings.json`. These are observed filename filters, not a compatibility guarantee. For both texture profiles, `calibrationReviewed` is `false`, `resourceInventoryComplete` is `false`, and `settings` is empty. This configuration supports bounded local planning only; it does not authorize an import. The FBX helper itself has not selected a file or verified import settings, final Import, processing, or output; `--submit` remains `LOCKED` because the helper's real import flow is not implemented and verified.

The helper's `--inspect` UIA attempt timed out at 45 seconds and returned **UNKNOWN**. A later real `--open-import-picker` invocation remained unresponsive for more than 60 seconds and was interrupted; no Windows picker was verified. The worker now bounds redirected stdout/stderr draining to 3 seconds after child exit and reports **UNKNOWN** if the pipes do not close, but this fix is not proven to explain the earlier hang. There was no UI retry. Recheck the README for newer evidence before acting; `--submit` remains locked.

TaleWorlds documents **Assets**, **AssetSources**, and **AssetPackages** as distinct editable-source and distribution locations, but the alleged fatal folder-precedence rule is not verified. Preserve these folders. Treat **Add Leaf Bones** as a manual export checklist item and do not claim **_notused** transfers weights; see TaleWorlds' [asset naming conventions](https://moddocs.bannerlord.com/asset-management/asset-types/asset_naming_conventions/).

For sprite atlas generation and Resource Browser atlas import, use **bannerlord-resource-browser**.
