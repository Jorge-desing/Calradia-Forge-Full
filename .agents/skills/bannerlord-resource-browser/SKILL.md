# Bannerlord Resource Browser

Use this skill for the project's Gauntlet sprite atlas and Resource Browser workflow. Keep evidence in three categories: **officially documented**, **observed in this project**, and **not verified**. A UI filter, picker opening, source build, file change, or metadata check does not by itself prove a successful import or correct runtime rendering.

## Sprite atlas workflow

- Keep source sprites under **modules/CalradiaForge/GUI/SpriteParts/ui_calradiaforge/** and follow the project asset README.
- Before starting the Modding Kit, build the module into both `Modules\CalradiaForge\bin\Win64_Shipping_wEditor` and `Modules\CalradiaForge\bin\Win64_Shipping_Client`. TaleWorlds warns that an incomplete module build can crash the Kit at launch. See [Generating and Loading UI Sprite Sheets](https://moddocs.bannerlord.com/asset-management/generating_and_loading_ui_sprite_sheets/).
- Review the existing build scripts before running them. **[Build-CalradiaForge-UiAssets.bat](../../../tools/Build-CalradiaForge-UiAssets.bat)** stages an isolated module input and invokes the official SpriteSheetGenerator; it generates the source atlas and SpriteData, not the runtime TPAC. The PowerShell script records that the installed `SingleModule` CLI path once exited successfully without producing Engine sprite files, so an exit code of zero alone is not enough: confirm the expected atlas, SpriteData, and Config outputs and run post-generation validation. Run the BAT in its supported visible console; do not assume redirected standard input is a supported way to dismiss the generator.
- TaleWorlds documents adding sprite PNGs under **GUI/SpriteParts**, running SpriteSheetGenerator, which creates **Assets**, **AssetSources**, and module SpriteData, then importing the generated atlas from Resource Browser. The documented atlas flow is: launch the Modding Kit from Steam, select the module in the Launcher's Mods section, and start it; at the main menu open the console and submit **resource.show_resource_browser**; then select the module, open **Assets/GauntletUI**, scan new asset files, select the sprite category, and invoke Import. See [Generating and Loading UI Sprite Sheets](https://moddocs.bannerlord.com/asset-management/generating_and_loading_ui_sprite_sheets/).
- Each `GUI/SpriteParts/ui_{category}` folder is one sprite category whose sprites load and unload together. Split infrequently used screens into separate categories to avoid loading unrelated sprites. For an optional screen, the documented manual lifecycle is to get the category from `UIResourceManager.SpriteData`, call `Load(resourceContext, resourceDepot)` before loading its Gauntlet movie, and call `Unload()` during that screen's cleanup. `AlwaysLoad` loads a category on startup and keeps it resident until game close unless the developer explicitly unloads it; this trades more memory for shorter UI load time. Calradia Forge's `ui_calradiaforge` category is marked `AlwaysLoad` in Config and generated SpriteData; see the [SpriteParts README](../../../modules/CalradiaForge/GUI/SpriteParts/README.md) and [Rev025 validation record](../../../docs/append/Rev025-Gauntlet-imagegen-atlas-validation-2026-09-24.md). TaleWorlds documents both category strategies and the lifecycle example in [Generating and Loading UI Sprite Sheets](https://moddocs.bannerlord.com/asset-management/generating_and_loading_ui_sprite_sheets/).
- Do not conflate atlas scanning/import with the generic **Import New Assets** context-menu flow. Observed in this project: in the Resource Browser, right-click an empty area of the central **Assets** pane (not the left module/folder tree), then choose **Import New Assets**. This opens the Windows file picker for adding asset files. A picker opening does not prove that a selected file will be accepted, imported, compiled, or rendered. Keep this flow distinct from scanning the atlas and importing a sprite category.

## Opening the Mod Menu After Import

- After an Editor import, close the Resource Browser and exit the Modding Kit completely before launching Bannerlord; the Editor and game should not be left open together. Build both Client and Modding Kit profiles before launching after code changes.
- At the singleplayer main menu, press Calradia Forge's configured `Settings.Hotkey` (default `F10`) to inspect its overlay; press the same key to close it. For the F10 held-state/rising-edge fallback, follow [bannerlord-gauntlet-ui](../bannerlord-gauntlet-ui/SKILL.md) and [.agents/rules/calradia_forge_ui.md](../../rules/calradia_forge_ui.md).
- Before each source correction, close Bannerlord and the Modding Kit and end/reset Ordenador/Computer Use; keep them closed through edits and builds. When a task requests or authorizes live review, the agent may launch the Steam game or Modding Kit with Calradia Forge enabled. Do not ask the user to open it first. After each live check, close Bannerlord and end/reset the Computer Use session before making another correction or finishing.
- Verify the actual overlay in game; the picker, Resource Browser, or TPAC file alone does not prove the menu rendered.

## Asset Browser search and texture inspection

- TaleWorlds documents an **Extras > Query Mode** option in the Asset Browser. It accepts SQL-like filters over asset properties; the documented example is finding textures with resolution greater than 1024. Use it to narrow the asset list, not as an import command. The guide does not specify the complete property schema or exact query grammar, so do not invent field names or automate a query until the current Editor confirms them. See [Filter Queries](https://moddocs.bannerlord.com/asset-management/asset-browser/filterqueries/).
- The Texture Inspector can display mip levels side by side when **Use Mipmap Blending** is enabled; the documented controls can adjust mip blend amounts/color, and **Recompile** applies that blend. Treat Recompile as a write operation against the selected resource: record the exact target and back it up before changing settings. A preview or recompile is not evidence that a newly generated sprite atlas was imported correctly. This behavior is documented in [Filter Queries](https://moddocs.bannerlord.com/asset-management/asset-browser/filterqueries/), but has not been exercised in this project.
- For ordinary textures, TaleWorlds documents importing through the Asset Browser and assigning them to materials through Material Editor. The `_d`, `_n`, `_s`, and `_h` suffixes are optional hints for albedo, normal, specular, and height textures; they can help first-import compilation rules and normal-slot autocomplete, but they do not validate a texture or guarantee acceptance. Keep this separate from the sprite-atlas category workflow. See [Textures](https://moddocs.bannerlord.com/asset-management/asset-types/textures/) and [Naming Conventions](https://moddocs.bannerlord.com/asset-management/asset-types/asset_naming_conventions/).

## Evidence and verification

- The project [SpriteParts README](../../../modules/CalradiaForge/GUI/SpriteParts/README.md) and [Resource Browser preparation script](../../../tools/Prepare-CalradiaForge-ResourceBrowser.bat) describe the current local checks. Re-read them before operations because tool support and observed Editor state can change.
- A Resource Browser observation is verified only for the resource properties actually visible. For a newly generated atlas, confirm the expected resource name, type, and dimensions in Resource Browser; then check the panel in the game's main menu for rendering, contrast, and interaction. If either live check is unavailable, report it as pending.
- Keep source and runtime observations separate. On 2026-09-23, the Resource Browser showed an older atlas resource at **2048 × 256**. [Rev025](../../../docs/append/Rev025-Gauntlet-imagegen-atlas-validation-2026-09-24.md) records a subsequently regenerated source atlas at **2048 × 128**, with 13 registered sprite parts. At that revision the installed TPAC predated the new atlas; it was not imported or replaced, and no live render was observed. Do not present the older Resource Browser view as verification of the newer source atlas or TPAC.
- **TPAC handling:** The user removed TpacTool after frequent reader errors; do not install, restore, or use it as an import, deployment, or release gate. Its parse errors do not establish that a TPAC is corrupt. A file's presence, size, hash, or header check does not prove that its texture payload decodes or renders. Use Resource Browser's built-in import/update flow, preserve the imported Steam TPAC during code deployment, and verify the referenced sprites in the running game. Back up and record a hash before any intentional TPAC replacement.
- State validator scope precisely. **[validate_game_icon_assets.py](../../../tools/validate_game_icon_assets.py)** checks authoring inputs such as prefab sprite references, icon attribution and safe paths, source SVG/PNG assets, and `AlwaysLoad`; after generation it checks SpriteData registrations/bounds and source-atlas dimensions. Its optional TPAC check is only a marker/header presence check. **[Validate-CalradiaForge-DecorativeSprites.py](../../../tools/Validate-CalradiaForge-DecorativeSprites.py)** checks the four decorative PNGs, their registered dimensions, exact source-to-atlas pixel crops when SpriteData is current, bounded prefab placements, passive event handling, and modeled intersections with controls, text, input surfaces, and evidence states. The structural auditor and automated tests remain source-level checks. None of these decodes/verifies the runtime TPAC texture payload or proves rendering in Bannerlord; that requires the corresponding live observation.
- Back up any existing TPAC separately and verify its SHA-256 before replacement. Stop when the target, overwrite prompt, selected resource, or UI state is ambiguous.

## Editor automation and asset folders

- Distinguish the visible **Resource Browser** window from **Edit Mode**; they can belong to the same process. Read-only automation must target the configured Editor process and exact visible window. If the window match is missing or ambiguous, the accessibility tree is unavailable, or UIA times out, stop and record **UNKNOWN**. Do not fall back to global window search, retry, send guessed coordinates, or close an unexpected dialog.
- The local observation dated 2026-09-23 showed **Modules > CalradiaForge > Assets > GauntletUI** and an existing atlas resource at 2048 × 256 in the Resource Browser. The separate Windows picker displayed the combined filename filter `*.tif;*.psd;*.dds;*.bmp;*.tga;*.png;*.hdr;*.exr;*.trf;*.fbx;*.stsdk`. The helper's texture profiles use only the observed raster subset **.tif, .psd, .dds, .bmp, .tga, .png, .hdr, and .exr**. These observations establish only which patterns the picker displayed; they do not establish import compatibility, settings, or output.
- TaleWorlds defines **Assets** as editable TPAC metadata, **AssetSources** as imported source files, **AssetPackages** as read-only client packages, **EmAssetPackages** as read-only Editor packages, and **DsAssetPackages** as read-only server packages. `RuntimeDataCache` holds generated per-asset engine data; the docs say it can be deleted but may take time to regenerate. The package folder used for distribution depends on the client, Editor, or server build. Asset overrides match by name with module loading order taken into account. Preserve the authoring/package folders; do not delete folders as a remedy for an unverified directory-precedence or crash claim. See [Adding and Overriding Assets](https://moddocs.bannerlord.com/asset-management/asset-types/overriding_assets/).

For FBX batch planning or the experimental standalone helper, use [bannerlord-fbx-importer](../bannerlord-fbx-importer/SKILL.md). Do not represent that helper as an official TaleWorlds API or as part of the game module.
