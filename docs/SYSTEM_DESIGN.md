# Calradia Forge 25.0.0 system design

Calradia Forge has three boundaries: a Bannerlord module on the game thread, a standalone .NET 8 desktop workbench, and a public C# SDK. The module and SDK target the installed Native 1.4.8 surface. The desktop app remains separate from `Modules` and connects only over a local named pipe.

## Evidence flow

`ForgeAnalysisRequest` contains an explicit local target and bounded file/byte limits. `ForgeAnalysisResult` returns the analyzer identity, state, provenance, timestamps, source evidence, and a bounded list of `ForgeDiagnosticFinding` records. Built-in analyzers never load target assemblies or execute target code. SDK extensions implement `IForgeAnalyzer` through `ForgeApi.Analyses`; state-changing analyzers are rejected at registration.

Folder scans use an explicit, cancellable traversal rather than following directory links. The walker does not follow a selected root or nested reparse point and caps one scan at 10,000 discovered directories (including the root), depth 64, and 200,000 filesystem entries; `MaximumFiles` defaults to 1,000 and is clamped to 1–2,000. Cancellation is checked during directory and entry traversal and while bounded file reads are consumed. Analysis returns `Cancelled` with unavailable provenance when the token is signaled; it does not claim the partial work as a completed result. A reached bound, unreadable path, or skipped reparse point marks the result truncated and adds an `analysis_scan_incomplete` warning instead of presenting a partial scan as complete.

The `SubModule.xml` module validator applies matching root/tree safeguards independently: it examines at most 10,000 directories including the selected root, depth 64, and 200,000 filesystem entries, and validates at most 10,000 additional XML files. Reparse points are skipped and any bound or access failure produces `analysis_scan_incomplete`. Its public synchronous `Inspect(string)` retains its existing behavior; the built-in analyzer uses an internal token-aware overload that checks cancellation during traversal, dependency processing, and XML reads. Nested file traversal and dependency-cycle detection use explicit stacks so deep trees or dependency chains do not consume the call stack. Declared incompatibilities are reported only when the named module is present in the inspected root.

The standalone `ModRuleAuditor` uses the same bounded directory, entry, depth, and input-byte limits. Reparse points are never followed; an incomplete traversal, unreadable or oversized input, or malformed XML creates an error finding rather than a false pass. Its tools exemption applies only to the repository-root `tools` directory after the root is identified by expected repository markers. The static Pulse rule requires a verifiable numeric `MinimumIntervalMilliseconds` of at least 50 ms and masks comments and string literals before inspection. This is an audit rule; runtime ForgeWeave separately enforces its 250 ms subscription minimum. `ForgeAnalysisCatalog.BuiltInAnalyzerIds` is exposed as a read-only collection. Public engine helper methods without a verified implementation throw `NotSupportedException` instead of silently returning success.

Archive preflight checks the selected file's size against `MaximumBytesPerFile` before constructing `ZipArchive` or reading its directory entries. The default per-file limit is 4 MiB; Core clamps ordinary analyzer inputs to 1 KiB–16 MiB. An oversized archive is marked truncated with `archive_size_limit`, and no ZIP entries are inspected. Before constructing `ZipArchive`, it reads the bounded end-of-central-directory record and rejects unreadable or multi-disk directories and archives declaring more than 10,000 entries; those results are truncated and no entry objects are materialized. For an accepted archive, the analyzer materializes at most 10,000 directory entries and inspects at most the request's `MaximumFiles` entries (clamped to 1–2,000), reports only entries actually inspected in `FilesExamined`, and marks omitted entries truncated.

The asset analyzer checks Gauntlet sprite metadata against source parts and generated atlases: category/sheet references, bounds, safe part filenames, and source dimensions. PNG inspection reads only the 24-byte signature/IHDR header; it does not decode image data, validate CRCs, or make visual-quality claims. TPAC analysis reads its 36-byte v2 header, enforces a bounded nonzero declared asset count, and bounds the table-of-contents range to the file, but does not parse asset entries or texture payloads. Other versions are reported as unsupported by this analyzer without applying v2 offsets. The optional preflight uses TpacTool for metadata parsing and reports a separate outcome; a reader failure alone does not establish corruption, and neither result proves visual rendering.

Runtime capabilities are explicit. A host reports `IForgeRuntimeCapabilities` before an extension calls input, serialization, debug rendering, or agent inspection. An unavailable service throws `ForgeCapabilityUnavailableException`; it does not return a plausible empty result.

## ForgeWeave

ForgeWeave dispatches copied scalar data from Forge-owned official callbacks on the game thread. Registration freezes descriptors, orders handlers deterministically, applies context and writer gates, isolates exceptions, and quarantines repeated failures. Equal-priority dependency planning uses a binary min-heap of ready handlers keyed by ordinal case-insensitive ID, preserving the existing deterministic order without repeatedly sorting the ready set. Plans for non-`Custom` events are reused until registration changes; open-ended `Custom` topics are planned per dispatch and not cached. Replay Lab retains a bounded record of host events and replays one selected retained sequence only after handler opt-in and exact context matching. Replays retain normal test-mode and copied-campaign protection, never accept a replacement payload, and are never retained as new sources.

## Transport and reporting

The desktop named-pipe protocol negotiates capabilities and returns session/report snapshots. Its local transport recovers from disconnection without exposing game objects. JSON and HTML report exports retain analyzers, evidence, journal records, replay outcomes, and limits. They do not assert that Forge observed every engine or third-party failure.

## Desktop presentation and measurement

The Desktop shell uses CommunityToolkit.Mvvm through a small compatibility surface in `MvvmPrimitives.cs`; this presentation dependency is not referenced by the game module. MaterialDesignThemes remains a Desktop presentation dependency. Font-independent WPF geometries provide semantic icons, including attributed Game-icons.net paths. `DesktopToolDefinitions` declares Desktop routes. Separately, the public game SDK's `[ForgeUiPage]` and `[ForgeUiCommand]` metadata is discovered only in the explicitly supplied module assembly. The host validates owner/prefab containment, ViewModel and command shape, duplicate IDs, `Command.Click` bindings, and open-time context/test/campaign-copy policy; it opens the extension prefab as its own Gauntlet layer rather than patching a shared view. This is not a sandbox for extension code. AsmResolver 6.0.1 is used both by the Desktop workbench and the game module to parse bounded PE/.NET metadata without loading or executing the analyzed assembly. Its optional version editor requires a no-write preview and writes only a new, backed-up output copy. DocFX runs during builds to make the SDK reference and localized offline help source; it is not a runtime dependency.

`DesktopWorkspaceService` owns file analysis, template generation, session queries, and report material without accessing WPF controls. `DesktopSessionService` owns cancellable named-pipe connection and reconnection. Disconnected, unsupported, missing-input, and state-changing paths state their limit explicitly. `DesktopLocalizationService` and `DesktopThemeService` own Forge resources; all thirteen language dictionaries and all three theme dictionaries use authoritative key parity. `DesktopPreferenceService` atomically stores only the Desktop theme and language under the user data folder, with safe fallback for malformed files. Technical evidence is never passed through these services. `DesktopMetricsService` retains at most 64 short measurements. Synchronous operations include owning-thread allocation counts; asynchronous operations retain elapsed duration and explicitly leave allocation bytes unavailable because a thread-local counter cannot cover awaits or thread switches. Every sample includes its scope limit and cannot attribute performance to Bannerlord or another mod.

## Distribution and execution

The packager derives the release version from `Directory.Build.props` and audits XML, manifests, assembly version, archive paths, hashes, duplicate entries, excluded game assemblies, save absence, and expected content. The current source property is 25.0.0; this source update does not regenerate existing archives. The game probe is preflighted, then starts through Steam's Bannerlord application id. A failed preflight or failed Steam probe is reported with its artifact; neither is recorded as a successful native test.
