# Verified hook routing and package safety — 2026-10-02

**Version:** Calradia Forge 25.2.0, unchanged; SDK API 13
**Scope:** Core test registry, Gauntlet Hook Workbench bindings, package output safety, bilingual patch guidance, and distribution validation.

## Observed issue and technical justification

Final review identified a cross-registry ID collision in the test host: `TestEngine.RegisterTranspiler` forwarded registration directly to the hook service, bypassing the case-insensitive ID set used by commands. A separate Gauntlet regression showed that route-derived visibility could remain stale when section navigation or evidence focus changed. Packaging also needed an explicit overwrite boundary because rerunning into the same artifacts directory could replace previous archives or manifests.

## Technical solution and architectural decisions

`RegisterTranspiler` now validates and reserves IDs under `registryGate`, shares the host's global ID set, and rolls back the reservation if service registration fails. Gauntlet publishes notifications for `IsPatchPreflightActive` and `IsHookWorkbenchVisible` on layout/route changes and when evidence focus changes. The Hook Workbench remains a conditional action surface within Patch Preflight; it does not replace the navigation rail or evidence ledger. Package outputs can be directed only to ignored `artifacts/` subdirectories, existing targets are rejected before build, and cleanup touches only staging paths created by the current package invocation.

## Code, asset, and dependency changes

The work updates `TestEngine`, its global-ID regression, `PanelViewModel`, Gauntlet routing tests, package output/audit scripts, package launcher configuration, and the existing 13 language catalogs regenerated by the canonical build. No API version, dependency, product version, runtime hook contract, command, or IPC surface changed. Product version remains 25.2.0, SDK API 13, and MonoMod 25.3.6.
