# Rev115 — Hook ordering diagnostics and SDK v12 binary compatibility — 2026-10-02

This follow-up adds read-only diagnostics for declared hook ordering. Registration normalizes unqualified IDs and the `CalradiaForge.Hook.*` form before rejecting cycles among currently registered Forge hooks for the same exact target method. `cf.hook_status` reports priority and `Before`/`After` metadata; `cf.hook_order` classifies references against the current Forge inventory. External, ambiguous, and cross-target references remain unresolved. The output describes declarations and does not prove the effective MonoMod dispatch order.

A disposable binary consumer compiled against the SDK v12 registry contract loaded under SDK v13 and exercised the legacy test, command, and provider entry points. This fixture covers those exercised compatibility surfaces and is not a proof for every possible old consumer. Settings tests now redirect writes to a test-owned temporary documents root; atomic-save diagnostics include the destination and HRESULT, and cleanup failures are reported without hiding prior test failures.

The Release solution build completed with zero warnings and errors. BAT validation passed Core 413/413, the serial x64 detour/hook fixture, Desktop 65/65, ForgeWeave 73/73, WPF rendering with 295 cases and 308 layout passes, stateless acceptance 4/4, and Gauntlet structural checks. The WPF duration belongs to the render harness and is not a measurement of interactive application latency. The fixture is serial and does not prove safety when another thread is executing a target during mutation.

Finalizer callbacks are attempted after a failing Prefix/original/Postfix path only while the host callback gate remains open. A context transition or host unload may suppress the Finalizer; it is not an unconditional cleanup guarantee. No live Bannerlord hook application was performed.
