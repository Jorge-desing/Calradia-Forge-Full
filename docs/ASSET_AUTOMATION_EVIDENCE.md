# Asset automation evidence review

This review treats the supplied AI-generated infographic as a proposal to evaluate, not as Bannerlord documentation or an implementation specification. Calradia Forge targets Bannerlord 1.4.8. The infographic's title card says TaleWorlds v1.2+, but it does not provide a reproducible environment, test data, source code for its charts, or version-specific evidence for its batch-import claims.

## Supported workflow used by this project

For UI sprites, TaleWorlds documents source images under `GUI/SpriteParts/ui_<category>`, generation with `TaleWorlds.TwoDimension.SpriteSheetGenerator.exe`, and a separate Resource Browser import step. The browser scans new asset files and creates the runtime texture package after the author selects a category and imports the generated atlas. Calradia Forge follows that sequence with `Build-CalradiaForge-UiAssets.bat` and `Prepare-CalradiaForge-ResourceBrowser.bat`; its generation helper runs in a one-module staging tree, validates the generated atlas and sprite metadata, and requires a visible interactive console. The project has confirmed that the generator and its companion library exist in the user's installed editor directory. Presence is not evidence that a particular run completed.

The batch planner is a bounded inventory, not a compiler. Schema v4 records file evidence, whether the official sprite generator is present, `SpriteData` validity, exact atlas/category/sheet-name matches, each remaining manual step, elapsed planner duration, and the host process's peak working set when available. `manual-run-ready` means the expected executable and library were found; it does not mean the process ran. `SpriteData` parsing is limited to 4 MiB, prohibits DTDs, and disables external XML resolution. A predicted TPAC path is explicitly an expectation, not a generated-file observation. Resource Browser import and runtime TPAC verification remain `manual-required` or `not-attempted` until separately performed. The duration covers inventory, hashing, `SpriteData` parsing, and mapping; peak working set covers the PowerShell process lifetime, not allocations or game memory. Generator throughput, runtime performance, and crash reduction remain unmeasured.

## Safe automation boundary

1. Inventory candidate files with explicit file, directory, depth, and byte limits; hash only candidate files and keep the report outside the source tree.
2. For recognized UI sprite folders, check the official generator's presence, then let the author run the documented generator workflow in a visible console.
3. Import generated atlases through Resource Browser and verify the resulting TPAC separately. TpacTool may be used as an optional metadata reader where its version permits; it does not replace import or prove texture rendering.
4. Record unsupported formats, failed readers, and unrun stages as such. Never infer success from a process launch, filename extension, plausible file marker, or infographic metric.

## Read-only FBX text preflight

The Desktop **FBX ASCII Preflight** tool uses the bounded Core analyzer. `tools/Inspect-CalradiaForge-Fbx.bat` provides a separate PowerShell implementation for command-line use. Both are read-only; Desktop forwards cooperative cancellation into traversal and parsing, while the console BAT can be interrupted from its window. They report FBX ASCII model/geometry declarations, material declaration names without resolving them, geometry names with `.lodN` or `_lodN` suffixes, and Camera/Light model declarations as review-only scene-object hints. The CLI retains exact bounded Camera/Light totals and at most sixteen example node names per file. The community FBX import guide recommends limiting Blender export to selected objects to avoid importing unintended scene contents; the tool does not infer whether a Camera or Light is unwanted and never removes it. LOD gaps and repeated geometry names are review advisories, not import verdicts. Geometry declarations are preferred over paired Model nodes to avoid reporting a normal FBX model/geometry pair as a duplicate.

```bat
tools\Inspect-CalradiaForge-Fbx.bat -InputPath "C:\ModWork\AssetSources\armor.fbx" -OutputJson "C:\ModReports\armor-fbx.json"
tools\Inspect-CalradiaForge-Fbx.bat -InputPath "C:\ModWork\AssetSources" -OutputJson "C:\ModReports\fbx-inventory.json" -Recurse
```

The standalone BAT defaults cap a scan at 1,000 visited files, 10,000 discovered directories, depth 32, 256 MiB per file, 2 GiB total FBX bytes, and 10,000 parsed object declarations per file. The Desktop Core analyzer caps its scan at 1,000 FBX files, 10,000 directories, depth 32, 200,000 directory entries, 256 MiB per file, and 10,000 object declarations per file; it also stops at 2 GiB of discovered FBX input. Binary FBX is detected but not parsed by either implementation. Neither validates transforms, axes, dimensions, UVs, textures, material availability, weights, morphs, or TPAC output, and neither launches the editor or importer. Use the Resource Browser for actual import and inspect the resulting asset separately. The BAT test is `tests\CalradiaForge.FbxPreflight.Tests.bat`; Core and Desktop route fixtures run from the master test BAT.

Official references: [Generating and Loading UI Sprite Sheets](https://moddocs.bannerlord.com/asset-management/generating_and_loading_ui_sprite_sheets/), [Adding and Overriding Assets](https://moddocs.bannerlord.com/asset-management/asset-types/overriding_assets/), and [TpacTool upstream README](https://github.com/szszss/TpacTool#readme).

### Official console command clarification — 2026-09-23

TaleWorlds explicitly documents `Alt + backtick`, then `resource.show_resource_browser`, then Enter to open Resource Browser. Here Enter submits the typed console command. The guide does not describe a SpriteSheetGenerator stdin handshake, a PNG file-lock lifecycle, or sending a newline to that executable. It also confirms the generator creates `Assets`, `AssetSources`, and `SpriteData.xml`; this documents folder creation, not a conflict rule. TaleWorlds separately assigns editable asset metadata, source inputs, and published read-only TPACs to those directories and says authoring folders may be filtered before publication. It does not say empty authoring folders override `AssetPackages` or cause War Sails to crash. Do not delete authoring folders based on that unsupported causal claim.

The additional pasted C# proposal claims more than the official page establishes. The console command is documented as a manual procedure; `SetForegroundWindow`, a fixed `SendKeys` timing sequence, and automatic invocation are not. UI Automation exposes window events and close patterns, but the Editor's safe-recovery semantics after dismissing an import error are undocumented, so the helper continues to stop and leave unexpected dialogs untouched.

### Standalone FBX helper implementation status — 2026-09-23

`BannerlordFbxImporter` is a separate .NET 8 Windows experiment, not part of the game module or release ZIPs. Its current code adds four explicit planning profiles, bounded recursive scanning with duplicate-basename rejection, configured-only texture extensions, an explicit texture-assignment map, advisory bounded FBX ASCII material evidence, and an independently tested SHA-256 backup service. The backup service is not wired into import submission because submission remains locked.

`--inspect` is read-only and runs in a disposable worker with a timeout. One earlier snapshot read a window titled `Resource Browser` and 112 controls but did not establish a reliable parent chain for `Modules > module > Assets`. A later inspection timed out. The current desktop-control surface exposes no native application to this session, so no further input was sent to the Editor. This says nothing about whether the Editor remains open.

The three existing 22.0.0 ZIPs were not regenerated.

This is implementation and local-fixture evidence only. It does not establish texture formats accepted by Resource Browser, a complete installed-material inventory, import behavior, safe modal recovery, sprite-generator stdin behavior, or the alleged fatal precedence of empty `Assets`/`AssetSources` folders. Keep authoring folders intact.
