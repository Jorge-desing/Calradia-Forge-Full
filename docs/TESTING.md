# Running the short test suite

From the repository root, run `tools\Run-CalradiaForge-Tests.bat`. This `.bat` builds the solution in Release mode and delegates each suite to its own launcher: `CalradiaForge.ResourceBrowser.Tests.bat`, `Run-CalradiaForge-Core-Tests.bat`, `Run-CalradiaForge-ForgeWeave-Tests.bat`, `Run-CalradiaForge-Desktop-Tests.bat`, and `Run-CalradiaForge-Desktop-Render-Tests.bat`. Resource Browser tests cover dry-run safety, staged and collected hashes, version-mismatch reporting, backup creation, empty-TPAC rejection, and module-ID rejection. Use these batch files as the test entry points; do not open test executables directly. The .NET 8 suites run through `dotnet` and their DLLs, with native app-host generation disabled. The .NET Framework 4.7.2 Core suite is built as a library and its internal test runner is invoked inside `powershell.exe` by `Run-CalradiaForge-Core-Tests.ps1`; no Core test `.exe` is produced or started. Each suite launcher can be run by itself after a successful build. The main batch file continues through all selected groups, returns a failure code if any group fails, and pauses at the end when started interactively so the result remains visible.

`CalradiaForgeTests.bat` is the compatibility entry point and delegates to the same full suite. `tools\build.ps1` and the release packager use the shared entry point with `--skip-build --no-pause` after their solution build. `--core-only` runs Core and ForgeWeave, `--desktop-only` runs the two Desktop suites, and `--assets-only` runs the Resource Browser staging checks; `--no-pause` is intended for automation. A nonzero exit code indicates a failed build, missing test output, or failed test group. To include the installed-module scan, set `FORGE_TEST_MODULES` to the game's `Modules` folder before running the batch file; `tools\build.ps1` supplies this automatically unless `-SkipInstalledScan` is used.
