# Persistencia de la compatibilidad de Computer Use de Codex

Codex guarda Computer Use en una carpeta de runtime versionada. Una actualización oficial puede crear una nueva ruta `cua_node/<id-del-runtime>/bin/node_modules/@oai/sky/bin/windows`; por ello, el `version.dll` instalado junto a un helper anterior quizá no se use con el nuevo.

## Instalación administrada

Ejecuta `Manage-CodexCaptureCompatPersistence.bat Install` desde este directorio. Copia el `dist/version.dll` probado y su script de mantenimiento a `%LOCALAPPDATA%\OpenAI\Codex\CodexCaptureCompat`, registra sus hashes SHA-256 y crea e inicia la tarea visible de usuario `CodexCaptureCompat-RuntimeWatcher` en el Programador de tareas. Se ejecuta sin elevación al iniciar sesión y vigila únicamente `%LOCALAPPDATA%\OpenAI\Codex\runtimes\cua_node`; los eventos del sistema de archivos activan un análisis y hay un análisis de respaldo cada 15 segundos.

El vigilante reconoce solo carpetas directas de versiones con la estructura exacta del helper de Codex y un `codex-computer-use.exe` existente. Omite los puntos de reanálisis. Instala el DLL administrado cuando el destino no tiene `version.dll`; solo reemplaza otro DLL cuando el registro adyacente demuestra que el archivo actual ya pertenece a este proyecto. Copia los DLL y registros reemplazados a `backups` y verifica sus hashes SHA-256. Deja intacto cualquier DLL sin propiedad comprobable o con hashes distintos y registra el motivo en `maintenance.jsonl`.

Si una actualización oficial cambia los bytes del helper, pero conserva la misma ruta del runtime, el vigilante solo puede reconciliar la instalación cuando el registro adyacente tenga el esquema, el marcador de propietario y el valor `managedBy` esperados, la ruta exacta del helper y campos SHA-256 válidos. Si existe `version.dll`, sus bytes deben coincidir con el hash del DLL indicado en ese registro antes de reemplazarlo; si falta, el registro válido de esa misma ruta permite restaurarlo desde la carga útil propia del proyecto. Todo DLL presente cuyos bytes no coincidan con el hash registrado se considera inesperado y se conserva. El cambio de hash del helper, por sí solo, no demuestra que el registro o el DLL pertenezcan al proyecto.

Se rechaza cualquier ruta candidata cuyo recorrido pase por un junction u otro punto de reanálisis; el vigilante no sigue esos enlaces, incluidos los que aparezcan en la raíz del runtime, la carpeta de versión o cualquier nivel anidado de la ruta del helper. La tarea programada aplica una recuperación acotada: hasta tres reinicios, separados por un minuto, si el vigilante termina inesperadamente.

El vigilante no modifica los archivos de la aplicación Codex ni `codex-computer-use.exe`, no solicita privilegios elevados y no termina Codex ni el helper. Si un helper nuevo inicia antes de que el vigilante copie el DLL, el proceso actual no puede cargarlo retroactivamente; surtirá efecto la próxima vez que se inicie ese helper. Después de una actualización oficial, consulta `Manage-CodexCaptureCompatPersistence.bat Status` y verifica Computer Use con una captura real antes de considerar validado el nuevo runtime.

Ejecuta `Manage-CodexCaptureCompatPersistence.bat Uninstall` para quitar únicamente la tarea programada administrada. La copia estable del DLL, el script, los registros y los respaldos se conservan. Puedes volver a registrar la tarea con `Install`. Para quitar un DLL de un runtime concreto, usa el desinstalador existente `Install-CodexCaptureCompat.bat` con la ruta exacta de ese helper.

La suite de fixtures es `tests\Test-CodexCaptureCompatPersistence.bat`; el punto de entrada de compilación y pruebas también la ejecuta mediante `tools\Build-Test-CodexCaptureCompat.bat`. Las pruebas cubren detección de nuevos runtimes, idempotencia, alcance de ruta, protección de archivos ajenos, actualización administrada y respaldos verificados. Aprobar los fixtures no valida un runtime futuro de Codex ni una captura en vivo.
